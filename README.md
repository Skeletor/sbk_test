# Тестовое задание для СБК


## Описание

Проект представляет собой GUI-клиент для наблюдения за устройствами. При запуске приложение запрашивает топологию устройств, а затем периодически получает новые события. Интерфейс состоит из дерева текущего состояния устройств и журнала событий.

Приложение поддерживает два транспорта:

- `http` - получение данных от HTTP-сервера;
- `mock` - встроенный источник тестовых данных, позволяющий запускать приложение без сервера.


## Архитектура

Проект разделён на несколько слоёв:

- `app/controller` управляет опросом, транспортом и обработкой состояния устройств;
- `app/domain` содержит общие типы предметной области;
- `app/ui` содержит Qt Widgets, модели представления и presenter;
- `app/config` загружает настройки отдельных модулей;
- `tests` содержит тесты на базе Qt Test.

Контроллер и его дочерние объекты работают в отдельном потоке. Взаимодействие с GUI-потоком выполняется через сигналы и слоты Qt. Транспорт скрыт за общим интерфейсом, поэтому HTTP-реализацию можно заменить встроенной mock-реализацией или новым транспортом без изменения UI.
Стилилзация и красота интерфейсов не выполнялась в угоду скорости разработки основного функционала.


## Требования

- Qt 5.12 с модулями Core, Gui, Widgets и Network; для тестов также требуется Testlib;
- C++17;
- qmake и make.


## Сборка и запуск

Из корня проекта:

```bash
mkdir -p build
cd build
qmake ../sbk_test.pro
make -j$(nproc)
./app/sbk_test
```


## Сборка и запуск тестов

Тестовый подпроект включается флагом `build_tests`. Собрать и запустить из корня проекта:

```bash
mkdir -p build-tests
cd build-tests
qmake ../sbk_test.pro CONFIG+=build_tests
make -j$(nproc)
./tests/sbk_tests
```


## Конфигурация

При первом запуске приложение автоматически создаёт файл с настройками по умолчанию. В Linux он расположен по адресу:

```text
$HOME/.config/sbk_test/config.ini
```

Настройки читаются при запуске приложения, поэтому после их изменения приложение необходимо перезапустить.
